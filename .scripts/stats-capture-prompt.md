# 📥 네이버 블로그 통계 일별 수집 (스크린샷 → JSON 정형화)

조회수 스냅샷을 `stats/daily/YYYYMMDD.json`으로 정형화한다. 해석·판정은 하지 않는다(주간에 `naver-stats-analyst`가 담당).

## ⚠️ 왜 스크린샷인가 (2026-07-07 확정)
`claude-in-chrome` 확장이 **네이버 도메인 전체(admin.blog.naver.com·creator-advisor.naver.com·blog.naver.com)를 안전 정책으로 하드 차단**한다. 사용자 사이트 허용으로도 안 뚫림 → **세션 기반 브라우저 자동 조회 불가**. 그래서 수집은 사용자 스크린샷을 태우는 방식으로 고정.

## 절차
1. 사용자가 **관리 → 통계 → 조회수 → 게시물별** 화면을 스크린샷(페이지 1~N 전부, 20/50줄 보기로 페이지 수 줄여도 됨)으로 떠서 `stats/`에 저장.
2. 각 이미지를 `Read`(vision)로 읽어 행을 추출: `제목`·`조회수`(숫자만)·`작성일`.
   - `작성일` 정규화: `N시간 전`·`어제` → 캡처일 기준 절대날짜(YYYY-MM-DD). `2026. 7. 3.` → `2026-07-03`.
   - 스크린샷엔 logNo가 안 보이므로 매칭 키는 `title`(발행일 보조). 제목 표기가 스냅샷마다 같아야 매칭됨.
3. `stats/daily/SCHEMA.md` 형식으로 `stats/daily/YYYYMMDD.json` 작성(캡처일 = 스크린샷 촬영일).
4. 완료 출력: `[STATS CAPTURE OK YYYY-MM-DD] N posts → stats/daily/YYYYMMDD.json`.

## 금지
- 성장배수·승자/패자·승격 판정 등 일체의 해석(주간 분석 몫).
- 브라우저로 네이버 통계 직접 조회 시도(하드 차단 — 시간 낭비).

## 캡처 팁 (매칭 정확도)
- 매번 **같은 정렬·같은 줄수 보기**로 떠 주면 제목 표기가 일관돼 스냅샷 간 매칭이 깔끔하다.
- 페이지가 많으면 최근 3~4주치(대략 상위 5~7페이지)만 떠도 충분 — 성숙 판정 대상은 발행 4주 이내다.
