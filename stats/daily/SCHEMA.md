# 📥 일별 통계 캡처 데이터 계약 (stats/daily/)

> 2026-07-07 도입. 수집(매일)과 분석(주간)을 분리하는 2층 구조의 **수집 결과 저장소**.
> 수집기(`.scripts/stats-capture-prompt.md`)가 매일 1개 파일을 쓰고, 분석 서브에이전트(`naver-stats-analyst`)가 이 폴더 전체를 읽어 시계열을 만든다.

## 파일명
`stats/daily/YYYYMMDD.json` — 캡처한 날짜(그날 조회수 누적 스냅샷).

## 스키마
```json
{
  "captured_at": "2026-07-07",           // 캡처 실행일 (KST)
  "source": "네이버 블로그 통계 > 게시물별 조회수",
  "note": "조회수는 글별 누적 총합(스냅샷). 분석은 스냅샷 간 델타로 계산.",
  "posts": [
    {
      "log_no": "223512345678",          // 있으면 필수 — 가장 안정적인 매칭 키(글 URL의 logNo)
      "title": "영동 물한계곡 여름 계곡 트레킹과 민주지산 원시림 피서, 충북 숨은 명소",
      "views": 365,                        // 그 시점 누적 조회수
      "published": "2026-06-29"            // 작성일(절대날짜로 정규화; '13시간 전' → 캡처일 기준 환산)
    }
  ]
}
```

## 수집 규칙
- **매칭 키**: 스크린샷 수집이라 logNo가 안 보임 → **`title`이 매칭 키**(발행일 보조). 매번 같은 정렬·줄수로 떠서 제목 표기를 일관되게. (혹시 logNo를 얻는 경로가 생기면 `log_no` 우선.)
- **작성일 정규화**: 통계 표의 `N시간 전`·`어제`는 **캡처일 기준 절대 날짜(YYYY-MM-DD)**로 환산해 저장. `2026. 7. 3.`은 `2026-07-03`.
- **전 페이지 수집**: 페이지네이션(1~N)을 끝까지 넘겨 그 시점 노출되는 모든 행을 담는다. 20줄/50줄 보기로 페이지 수를 줄여도 됨.
- **판정 금지**: 수집기는 숫자만 적는다. 성장배수·승자패자 해석은 분석 서브에이전트 몫.
- **누락 감지**: 특정 발행일 행이 통째로 비면(과거 06-18 누락 사례) `note`에 기록.
