# 📥 주간 통계 데이터 계약 (stats/weekly/) — 2026-07-07 신규 방식

> 사용자 캡처 방식 변경(2026-07-07): 기존 '글별 누적 조회수 전체'에서 → **주간 단위 '조회수 상위 100개'**로 전환.
> 사용자가 매주 캡처(20개씩 5파일 = top100)를 보여주면 Claude가 1개 주간 JSON으로 합쳐 저장하고, `naver-stats-analyst`가 분석한다.

## ⚠️ 이 데이터의 성격 (분석 전 반드시 인지)
- **metric = 주간 조회수** (그 주에 발생한 조회수). **누적 총합 아님.** → 성장배수(×N) 계산 금지, **주간 궤적의 모양**으로 해석.
- **coverage = top100 또는 top200** (주간 조회수 상위 N). **N 밖 롱테일은 검열되어 안 보임.**
  - **top200 권장**: 우리가 판정하는 admin_·rite_ 파일럿과 바닥 트래픽층(local_·gov_)은 원래 저조회라 top100엔 대개 미진입. 200이면 이들이 시야에 들어와 파일럿·바닥층 판정이 가능. 캡처 부담이 크면 최소한 **파일럿 재판정 주(rite_ ~7/26)·월1회 바닥 점검**엔 200으로.
  - coverage가 실제 몇인지 JSON에 반드시 기록(분석기가 검열 경계를 알아야 함).
- 매칭 키 = `title`(+`published`). 스샷엔 logNo 없음.

## 파일명
`stats/weekly/YYYYMMDD.json` — 그 주간의 기준일(주 종료일 권장, 예 일요일). 사용자가 알려준 주간 범위로 `week_start`/`week_end` 채움.

## 스키마
```json
{
  "week_label": "2026-W27",            // 선택
  "week_start": "2026-06-29",          // 주 시작(월)
  "week_end": "2026-07-05",            // 주 종료(일) — 파일명 기준
  "captured_at": "2026-07-07",
  "metric": "weekly_views",            // 그 주간 조회수 (누적 아님)
  "coverage": "top200",                // 상위 N: "top100"(5파일×20) 또는 "top200"(10파일×20) — 실제 값 기록
  "posts": [
    {"rank": 1, "title": "영동 물한계곡 여름 계곡 트레킹과 민주지산 원시림 피서, 충북 숨은 명소", "weekly_views": 365, "published": "2026-06-29"}
    // ... 최대 100 또는 200개
  ]
}
```

## 수집 규칙
- 캡처(각 20개)를 순서대로 합쳐 `rank` 부여(top100=5파일, top200=10파일). 순위가 불명확하면 `rank` 생략하고 `weekly_views` 내림차순으로만.
- `published` 정규화: `N시간 전`·`어제` → 절대날짜(YYYY-MM-DD). `2026. 7. 3.` → `2026-07-03`.
- 판정·해석 금지(분석 서브에이전트 몫). 여기선 숫자만.

### ⚠️ 캡처 화면 확인 — 1페이지 결손 사고 방지 (2026-08-09 추가)
`20260726` 백필 때 **랭킹 1페이지(1~20위)가 세트에 없어** 부분 커버리지(`rank21-200`)로 저장해야 했다. 원인 = `(1).jpg` 자리에 **다른 화면**이 들어갔음.

| ✅ 필요한 화면 (조회수 순위) | ❌ 혼동되는 화면 (글 목록) |
|---|---|
| 맨 왼쪽에 **순위 숫자** 칸 | 순위 칸 **없음**, 제목이 「전체보기 N개의 글」 |
| **「글」 타입 칸**이 따로 있음 | 타입 칸 없음 |
| 작성일에 **요일** — `2026.07.23. (목)` | `20시간 전` 같은 **상대시간** |
| 조회수 = **그 주 조회수** | 조회수 = **누적** |

- 합치기 전 **첫 파일이 rank 1로 시작하는지 반드시 확인**한다. 21로 시작하면 1페이지 결손이다.
- 결손 시: `coverage`를 `"rankA-B"` 형식으로 적고 `coverage_note`에 사유·사용 제약을 남긴다. **네이버 주간 통계는 소급 조회가 안 될 수 있어 재캡처가 불가능할 수 있다**(2026-08-09 확인: 주간 단위는 다음 주에 발표).

### 🔴 커버리지 깊이를 섞어 통계를 내지 말 것 (2026-08-09 — 실제 오류 사례)
주간마다 N이 다르면(top100·top200·top240·top260·부분) **중간값·평균을 여러 주에 걸쳐 합산하는 순간 대역 선택이 곧 값이 된다.** 좁은 대역을 고르면 값이 저절로 올라간다.

실측 (8주, 발행 4주 이상 정상상태 주간 중간값 → 월당 환산):

| 계산 대역 | 국내여행 | 생활정보 | 비율 |
|---|--:|--:|--:|
| 전체 관측 (혼재) | 135 | 131 | 1.03 |
| rank 21~200 | 152 | 148 | 1.03 |
| rank 21~100 | 344 | 322 | 1.07 |

- ❌ **절대 수준을 이 데이터로 확정하지 말 것.** 컷 없는 데이터(예: 카테고리별 최근 20개 전수)와 같은 축에 올리는 것도 금지.
- ✅ **대역에 강건한 것만 결론으로 쓴다** — ① 유형 간 **비율**(위 표에서 1.03~1.07로 안정) ② **성숙 곡선의 모양**(정점 2주차) ③ **같은 나이·같은 컷에서의 코호트 비교**.
- 여러 주를 합산할 땐 **모든 주가 완전히 덮는 공통 대역**을 명시하고 그 안에서만 계산한다.
